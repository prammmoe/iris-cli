Iris is a local command-line companion for personal todos, work logs, registered Git repositories, and everyday Git actions. Its data is stored locally in SQLite. It does not require a server or an account.

## Requirements

- Rust toolchain with Cargo
- Git, for Git-related commands
- Ollama with `qwen3:1.7b`, only for `iris compose commit`

Install the compose model when needed:

```sh
ollama pull qwen3:1.7b
```

## Install and run

Build a release binary:

```sh
cargo build --release
```

Run it from the repository during development:

```sh
cargo run -- <command>
```

For example:

```sh
cargo run -- todo add "Review pull request"
```

## Local data

Iris stores its SQLite database as `iris.db` in its operating-system data directory. Set `IRIS_DATA_DIR` to keep the database in a specific directory, which is useful for testing or separate profiles:

```sh
IRIS_DATA_DIR="$PWD/.iris-data" iris today
```

The directory is created automatically.

## Commands

### Todos

```text
iris todo add <title>    Add an open todo
iris todo list           List open todos
iris todo done <id>      Complete an open todo
```

Todo titles cannot be empty.

### Work log

```text
iris log <message>       Save a work-log entry
iris log today           Show entries from the current local calendar day
```

Work-log messages cannot be empty.

### Registered repositories and dashboard

Registered repositories let Iris include commit activity in its dashboard. They are separate from the current-directory Git shortcuts.

```text
iris repo add <path>     Register an existing Git work tree
iris repo list           List registered repositories
iris repo remove <name>  Remove a registered repository

iris git today --all     Show today's commits for registered repositories
iris today               Show open todos, today's logs, and Git activity
```

Repository names are derived from the final directory name. `iris repo add` rejects paths that are not Git work trees.

### Existing Git commands

These commands can run in the current Git repository or use a registered repository with `--repo <name>`.

```text
iris git remote add <name> <url>
iris git remote list
iris git remote remove <name>
iris git fetch [remote]
iris git pull [remote] [branch]
iris git push [remote] [branch]
```

### Current-directory Git shortcuts

Run these from inside a Git work tree. They do not accept `--repo` and execute Git in the current directory.

| Iris command | Git command |
| --- | --- |
| `iris forge all` | `git add .` |
| `iris forge` | interactive `git add -- <paths...>` |
| `iris dispatch` | `git push` |
| `iris realm` | `git branch` |
| `iris realm all` | `git branch --all` |
| `iris vault` | `git stash` |
| `iris chronicle` | `git log` |
| `iris inspect` | `git status` |
| `iris outpost` | `git remote` |
| `iris outpost from <url>` | `git remote add origin <url>` |

`iris forge` lists all tracked and untracked changes with a number and path. Select one or more files by number, path, or a combination separated with commas:

```text
1  src/main.rs
2  notes with spaces.md
Select files to add (for example 1,3,src/main.rs): 1,notes with spaces.md
```

Selections are deduplicated. Empty input, an invalid selector, or no changes cancels the operation without running `git add`.

Git output is passed through on success. When Git fails, Iris retains Git's stderr and adds an Iris error summary. A shortcut run outside a Git repository fails before the Git operation is attempted.

## Compose a commit message

Stage the intended changes first, then run:

```sh
iris compose commit
```

For a registered repository instead of the current directory:

```sh
iris compose --repo <name> commit
```

Iris reads the complete staged diff and sends it to the local `qwen3:1.7b` Ollama model. The model is instructed to return English plain text only with:

1. One lowercase Conventional Commit subject using `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, or `chore`.
2. A subject no longer than 72 characters and without a trailing period.
3. `Changed` and `Why` sections with bullets based only on the staged diff.
4. For `fix:` subjects only, a `Bugs And Fixes` section with `Bug:` and `Fix:` bullets.

Iris validates that structure before showing a preview. An invalid model response is rejected and cannot be confirmed as a commit. After the preview, Iris asks:

```text
Create this commit? [y/N]
```

Only `y` or `yes` commits. Any other response cancels the operation. Iris then rereads the staged diff. If it changed after the preview, Iris cancels the commit so the preview cannot approve a different diff.

## Development

Run the full test suite:

```sh
cargo test
```

Check formatting and whitespace before submitting changes:

```sh
cargo fmt --check
git diff --check
```

The test suite uses temporary directories and temporary Git repositories. It does not modify a user's configured repositories.

## Project layout

```text
src/application.rs     Application rules, compose validation, and selection logic
src/domain.rs          Domain data and typed Git operations
src/ports.rs           Storage, Git, and commit-composer boundaries
src/infrastructure.rs  SQLite, Git process, and Ollama implementations
src/main.rs            Clap command-line interface and terminal interaction
tests/cli.rs           End-to-end CLI tests
```
